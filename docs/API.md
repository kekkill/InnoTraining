# Поведение API

Все основные маршруты начинаются с `/api/v1`. JSON — camelCase. Защищённые запросы передают `Authorization: Bearer <accessToken>`. JWT действует 15 минут. Владельца товара определяет сервер из токена; поле владельца в запросе создания не принимается.

## Users, порт 5081

| Метод | Маршрут | Действие |
| --- | --- | --- |
| POST | `/auth/register` | Регистрация и письмо подтверждения |
| GET | `/auth/confirm-email?token=...` | Подтверждение почты |
| POST | `/auth/resend-confirmation` | Повторное письмо для неподтверждённого аккаунта |
| POST | `/auth/login` | Получение JWT |
| POST | `/auth/forgot-password` | Отправка кода восстановления |
| POST | `/auth/reset-password` | Смена пароля по коду |
| GET | `/users/me` | Текущий пользователь |
| GET | `/users?page=1&pageSize=20` | Список пользователей, Admin |
| GET | `/users/{id}` | Пользователь, сам владелец или Admin |
| PUT | `/users/{id}` | Изменение имени, сам владелец или Admin |
| POST | `/users/{id}/deactivate` | Деактивация, сам владелец или Admin |
| POST | `/users/{id}/activate` | Активация, Admin |
| PATCH | `/users/{id}/role` | Роль User/Admin, только Admin |
| DELETE | `/users/{id}` | Soft delete, сам владелец или Admin |

При регистрации нельзя самостоятельно назначить Admin. Начальный Admin создаётся из Bootstrap-настроек. Администратор не может удалить, отключить или понизить свою роль.

После смены пароля, роли, активации или деактивации старые JWT перестают работать. После активации нужен новый вход. Пять неверных попыток входа блокируют вход на пять минут.

Письма подтверждения и восстановления используют разные одноразовые коды со сроком один час. В базе хранится хеш кода. Для неизвестного email восстановление возвращает такой же ответ `202`, как для существующего аккаунта.

Внутренний маршрут `POST /internal/users/status` принимает `{"ids":["<guid>"]}` и заголовок `X-Service-Key`. Ответ содержит только `id`, `canAccess`, `authVersion`. Products передаёт список ID одним запросом.

## Products, порт 5082

| Метод | Маршрут | Действие |
| --- | --- | --- |
| GET | `/products` | Публичный каталог |
| GET | `/products/{id}` | Публичная карточка доступного товара |
| GET | `/products/mine` | Собственные не удалённые товары |
| POST | `/products` | Создание своего товара |
| PUT | `/products/{id}` | Изменение своего товара |
| DELETE | `/products/{id}` | Soft delete своего товара |

Создание, изменение, удаление и `/mine` требуют действующего JWT и доступного аккаунта. Даже Admin не может редактировать чужие товары.

Поиск: `search`, `minPrice`, `maxPrice`, `available`, `ownerId`, `page`, `pageSize`, `sort`. Сортировки: `newest`, `priceAsc`, `priceDesc`. Размер страницы — до 100. Ответ содержит `total`, `page`, `pageSize`, `items`; количество учитывает скрытие товаров недоступных владельцев.

`isAvailable` — атрибут для фильтрации. Значение false не удаляет товар из каталога автоматически. Деактивация пользователя и собственное удаление товара скрывают его независимо от этого атрибута.

## Ошибки

FluentValidation проверяет данные; middleware возвращает ProblemDetails. Статусы: `400` — данные/код неверны, `401` — нет актуального входа, `403` — нет прав, `404` — объект отсутствует или скрыт, `409` — конфликт, `503` — недоступна зависимость или отправка почты.

Неизвестные поля JSON и отсутствие обязательных параметров не игнорируются. Нельзя подставить роль при регистрации или другого владельца при создании товара.
